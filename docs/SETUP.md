# Setup

This covers running Vele locally, switching on each optional integration, and deploying it. Every integration is optional: without it the feature says it is unavailable rather than pretending to work.

## 1. Local development

Prerequisites: Node 22+, pnpm 10+, and PostgreSQL 16+ binaries (for the bundled local cluster) or any reachable PostgreSQL 16+ server.

```bash
pnpm install
pnpm setup
```

`pnpm setup` copies `.env.example` to `.env` and fills in `AUTH_SECRET`, `CRON_SECRET`, `TELEGRAM_WEBHOOK_SECRET` and `WHATSAPP_VERIFY_TOKEN` with fresh random values. It never overwrites a value that is already set.

### Database

Option A, the project-local cluster (recommended for development):

```bash
pnpm db:start     # initdb on first run, then starts PostgreSQL on 127.0.0.1:5434
pnpm db:status
pnpm db:stop
```

It finds `pg_ctl` on the usual install paths (set `PG_BIN` to override), stores data in `./.data/postgres`, listens on localhost only with trust auth for the `vele` user, and creates the `vele` and `vele_test` databases. Change the port with `LOCAL_PG_PORT`.

Option B, your own server: set `DATABASE_URL` (and `TEST_DATABASE_URL` for the test suite). The role needs permission to create the `btree_gist` and `pg_trgm` extensions the first migration installs.

Then apply migrations to both databases:

```bash
pnpm db:deploy
DATABASE_URL="$TEST_DATABASE_URL" pnpm db:deploy     # PowerShell: $env:DATABASE_URL=$env:TEST_DATABASE_URL; pnpm db:deploy
```

Optionally seed the demo account (`demo@vele.local`, password `vele-demo-password`) with a sample week:

```bash
pnpm db:seed
```

### Run

```bash
pnpm dev
```

Open http://localhost:3000 and create an account. `pnpm db:seed` fills a demo account with a sample week if you want data to look at. Accounts whose email is listed in `ADMIN_EMAILS` get the admin role, and with it the `/admin` page, when they sign up.

### Tests

```bash
pnpm test
```

Runs the scheduling engine's unit tests and the integration tests against `TEST_DATABASE_URL`. The integration tests reset that database, so never point it at real data. Email is forced to the console provider and the AI key is cleared for the suite. The live Gemini checks are opt-in and spend quota:

```bash
LIVE_AI=1 pnpm vitest run tests/live
```

## 2. The assistant (Gemini)

1. Create a key at https://aistudio.google.com/apikey.
2. Set `GEMINI_API_KEYS` in `.env`. Several keys, comma separated, are rotated one per request so a single key's rate limit doesn't stop you.
3. Optionally set `GEMINI_MODEL` (default `gemini-3.8-flash`). `gemini-3.1-pro-preview` is stronger at multi-step requests but is not available on a free-tier key.

Without a key, Vele runs in basic mode: a rule-based parser handles simple requests ("lunch with mom 1-3 saturday", "what's on tomorrow?") with the same tools and confirmation rules.

**Free-tier limits.** A free key allows only a few requests per minute and a small daily quota per model. One assistant reply can take two or three model calls (read the calendar, act, reply), so a handful of messages can use up a minute's allowance. Vele waits and retries once when Google says how long to wait. Otherwise it tells you which limit was hit, per minute or per day. The daily quota resets at midnight Pacific time. For regular use, enable billing on the key.

If the model stops partway through a turn (a quota error after an event was already added, for example), Vele reports what the tools already did instead of implying nothing happened.

## 3. Email

Email is used for invitations to people you add to events, booking confirmations, reschedule and cancellation notices, and magic sign-in links.

| `EMAIL_PROVIDER` | What happens |
| --- | --- |
| `console` (default) | Nothing is sent. In development the message is printed to the server terminal and recorded in the database; signed-in users can read theirs at `/dev/outbox`. Every screen that would say "sent" says "logged" instead. |
| `brevo` | Sent through Brevo's transactional API. Set `EMAIL_API_KEY` to a Brevo API key (`xkeysib-…`). |
| `resend` | Sent through Resend. Set `EMAIL_API_KEY` to a Resend API key. |

`EMAIL_FROM` must be a sender the provider has verified, for example `Vele <you@yourdomain.com>`. Brevo rejects unverified senders; verify a single sender or, better, authenticate your domain (SPF and DKIM) in the Brevo dashboard. Replies to invitations go to the account holder's own address.

Failed sends are retried by the maintenance job every 10 minutes, up to five attempts within two days. Each attempt is recorded, and the admin page shows delivery counts.

## 4. Telegram

1. Talk to [@BotFather](https://t.me/BotFather), run `/newbot`, and copy the token.
2. Set `TELEGRAM_BOT_TOKEN` and `TELEGRAM_BOT_USERNAME` (without the @). `TELEGRAM_WEBHOOK_SECRET` was generated by `pnpm setup`.
3. Deploy Vele somewhere Telegram can reach over HTTPS (or use a tunnel such as `cloudflared` or `ngrok` for local testing), then register the webhook:

   ```bash
   pnpm telegram:webhook https://your-domain.example
   ```

4. In Vele, open **Settings → Messaging → Telegram → Connect**. It shows a six-character code valid for 15 minutes; open the bot link (or send `/start CODE` to the bot) to link the chat to your account.

Telegram signs each webhook call with the secret in the `X-Telegram-Bot-Api-Secret-Token` header; requests without it are rejected. Messages are answered after the webhook returns, so Telegram never times out, and duplicate deliveries are ignored.

## 5. WhatsApp (Business Cloud API)

The WhatsApp channel is complete but needs a Meta business setup:

1. In [Meta for Developers](https://developers.facebook.com/), create an app, add the WhatsApp product, and note the **Phone number ID** and a permanent **access token** (system user token).
2. Set `WHATSAPP_API_KEY` (the access token), `WHATSAPP_PHONE_NUMBER_ID`, and `WHATSAPP_APP_SECRET` (App settings → Basic). `WHATSAPP_VERIFY_TOKEN` was generated by `pnpm setup`.
3. Configure the webhook in the WhatsApp settings: callback URL `https://your-domain.example/api/webhooks/whatsapp`, verify token = `WHATSAPP_VERIFY_TOKEN`, and subscribe to `messages`.
4. In Vele, **Settings → Messaging → WhatsApp → Connect**, then send `link CODE` to your business number.

Incoming requests must carry a valid `X-Hub-Signature-256` HMAC made with the app secret. Outside Meta's 24-hour customer-service window WhatsApp only allows template messages, so Vele can only reply to messages you send it.

## 6. Production

Vele is a standard Next.js app with one Node process and PostgreSQL.

```bash
pnpm install --frozen-lockfile
pnpm build           # runs prisma generate
pnpm db:deploy       # against the production DATABASE_URL
pnpm start
```

Checklist:

- `NEXT_PUBLIC_APP_URL` is the public `https://` origin. Cookies become `Secure` and HSTS is sent automatically.
- `AUTH_SECRET` and `CRON_SECRET` are long random values and differ from development.
- Run PostgreSQL with backups. Everything Vele stores is in that one database.
- Maintenance (expiring pending confirmations, retrying failed emails, pruning rate-limit buckets, old conversations and AI run logs) runs every 10 minutes inside the server process. On serverless hosts, where no process stays up, call it from a scheduler instead:

  ```
  POST /api/cron        (GET also works, for schedulers that only send GET)
  Authorization: Bearer <CRON_SECRET>
  ```

- Health check: `GET /api/health` returns 200 when the database answers and 503 when it does not.

Serverless platforms such as Vercel work. Set the environment variables, use a pooled `DATABASE_URL`, and add a cron entry for `/api/cron`.

## Troubleshooting

- **"The Gemini API rate limit for this key has been reached"**: see the free-tier notes above. Wait a minute, or enable billing.
- **"Today's free Gemini quota for this key is used up"**: resets at midnight Pacific time.
- **Emails say "logged"**: `EMAIL_PROVIDER` is `console`, or the key is missing. A `.env.development.local` file overrides `.env` in development, so check for one.
- **Brevo 400 "sender not valid"**: verify the `EMAIL_FROM` address or domain in Brevo.
- **Local database will not start**: run `pnpm db:status`, and set `PG_BIN` to the folder containing `pg_ctl`. On Windows the script starts PostgreSQL detached so it keeps running after the terminal closes.
- **Migrations fail on `CREATE EXTENSION`**: the database role needs permission to create `btree_gist` and `pg_trgm`, or ask your provider to enable them.
